# AI眼镜慧视校园操作手册

## 1. 概述

AI眼镜慧视校园是一套面向校园场景的智能识别辅助系统，旨在帮助教师在日常管理、学生画像了解、未来规划咨询、心理咨询辅助、考试巡查等场景中，快速获取学生基础信息与身份信息。系统以Rokid AI眼镜为交互终端，结合移动端应用与后端识别服务，实现“拍照识别、信息查询、眼镜展示”的完整闭环。

本系统整体采用前后端协同架构，主要由眼镜端、手机端和后端服务三部分组成：

- 前端移动端采用 `Kotlin` 语言开发，使用 `Android Studio` 作为主要开发工具，并基于 Rokid 的 `CXR-M SDK` 完成与眼镜设备的能力对接。
- 客户端通过 `CXR-M SDK` 实现蓝牙扫描、蓝牙初始化、蓝牙连接、拍照调用、图片数据回传以及眼镜端自定义视图展示等功能。
- 在蓝牙连接环节，系统通过过滤 Rokid 眼镜的服务 UUID，仅发现符合条件的目标设备，从而避免将普通蓝牙设备加入候选列表。
- 首次连接成功后，系统会记录眼镜设备名称、UUID 和 MAC 地址；后续再次进入应用时，可直接读取本地记录信息并调用 SDK 发起重连，从而提升连接效率。
- 后端采用 `Go` 与 `Python` 混合开发，其中认证、业务接口对接等能力由后端服务统一封装。
- 人脸识别部分采用 `InsightFace` 模型对人脸图像进行向量化处理，并封装为识别接口。
- 学校数据库中的学生人脸信息预先完成向量化处理并保存至向量库中；识别时，系统将实时采集的人脸与向量库中的学生人脸特征进行比对，得到匹配学生的学号信息。
- 后端再通过学校统一认证系统和学生信息查询服务，将学号映射为完整的学生基础信息，并返回给移动端。
- 手机端接收到学生信息后，再通过 `CXR-M SDK` 将识别结果渲染到 Rokid 眼镜端，实现教师佩戴眼镜时的实时查看。

系统运行流程如下：教师先在手机端完成眼镜蓝牙连接与账号登录，随后进入“慧视校园”应用页面，调用眼镜拍照能力采集学生人脸图像；后端完成识别与信息查询后，将学生姓名、学号、学院、专业、班级、年级等信息返回至移动端，并同步展示在眼镜端与手机端页面。

## 2. 操作方法

### 2.1 蓝牙连接眼镜

1. 启动应用后，系统默认进入设备连接页面。
2. 若此前已经连接过眼镜，页面会显示已记录的设备名称、MAC 地址和 UUID 信息，此时可直接点击“Reconnect”进行快速重连。
3. 若为首次使用，可点击“Scan”开始扫描设备。系统会基于 Rokid 眼镜服务 UUID 对蓝牙设备进行过滤，仅展示符合条件的眼镜设备。
4. 在扫描结果列表中选择目标眼镜设备，系统将先进行蓝牙初始化，再自动完成通信连接。
5. 当页面出现“Connected”状态后，说明手机端与 Rokid 眼镜已完成连接，此时点击 “To Use Glasses” 进入应用列表页面。

实现原理说明：

- 本系统基于 Rokid 提供的 `CXR-M SDK` 实现手机端与 AI 眼镜之间的蓝牙发现、初始化和连接。
- 在扫描阶段，客户端不会直接展示所有蓝牙设备，而是通过过滤 Rokid 眼镜特定的服务 UUID，仅保留符合条件的目标设备，从而减少误选普通蓝牙设备的情况。
- 首次连接成功后，系统会将眼镜设备名称、MAC 地址和 UUID 保存到本地存储中。后续再次打开应用时，可直接读取本地记录并发起重连，无需再次全量扫描。
- 连接建立后，手机端即可继续调用眼镜端拍照、数据回传、自定义视图显示等能力，为后续识别流程提供基础通信通道。

### 2.2 用户登录

1. 进入系统后，用户可点击底部导航中的“我的”页面查看当前登录状态。
2. 未登录时，页面会提示“请登录以继续使用完整功能”，点击“点击登录”按钮后，输入学号和密码即可完成登录。
3. 登录成功后，系统会保存访问令牌、用户身份和设备信息，并调用后端接口完成设备上线登记，确保后续识别请求可正常访问学校服务。
4. 再次进入“我的”页面时，可查看当前登录用户姓名、角色以及登录状态；如需退出，可点击“退出登录”按钮。

实现原理说明：

- 登录功能通过学校统一身份认证服务实现，用户输入学号和密码后，客户端调用后端认证接口，由后端与学校统一认证体系完成身份校验。
- 认证成功后，系统会返回访问令牌、刷新令牌、用户姓名、角色等信息，客户端将其安全保存，用于后续调用识别接口和学生信息查询接口。
- 登录完成后，系统还会执行设备上线登记，将当前登录人员与眼镜设备进行关联，确保后续请求来源清晰、权限可控。
- 当用户退出登录或令牌过期时，系统会主动调用设备下线接口并清理本地登录信息，避免无效会话继续访问学校业务数据。

### 2.3 进入校园识别应用

1. 在底部导航中切换回“主页”，进入应用列表页面。
2. 页面会显示“慧视校园1.0”应用卡片，点击“进入”即可打开校园识别功能页面。

实现原理说明：

- 应用列表页面用于承载多个眼镜相关功能模块，当前已集成“慧视校园”等业务入口，后续也可根据需要扩展更多校园服务应用。
- 用户在完成蓝牙连接和账号登录后，点击应用卡片即可进入对应业务页面。此设计将设备连接、身份认证与业务使用三个阶段解耦，便于统一管理和后续扩展。
- 进入校园识别应用后，页面将复用前面已经建立的蓝牙连接状态和登录态，无需重复认证或重复连接设备。

### 2.4 学生人脸识别

1. 进入“慧视校园”页面后，系统会显示“开始识别”和“手动识别”两个按钮。
2. 点击“开始识别”后，系统进入自动识别模式，按固定时间间隔调用眼镜拍照能力，持续抓拍并上传图像至后端识别服务。
3. 后端接口接收图像后，先使用 `InsightFace` 模型提取当前人脸特征向量，再与向量库中的学生人脸特征进行相似度匹配，得到对应学生学号。
4. 后端根据匹配出的学号调用学校学生信息查询服务，获取该学生的姓名、学号、学院、专业、班级、年级等完整信息，并将结果返回客户端。
5. 客户端在手机端页面展示识别结果的同时，也会通过 `CXR-M SDK` 将学生信息实时展示到 Rokid 眼镜端，便于教师边观察边查看信息。
6. 若仅需单次识别，可点击“手动识别”按钮，系统将执行一次拍照、识别与结果展示流程。
7. 若需停止连续识别，可再次点击“停止识别”按钮结束自动识别。

实现原理说明：

- 人脸识别部分采用 `InsightFace` 模型对学生人脸进行特征提取。系统会预先将学校人脸库中的学生照片进行向量化处理，并将向量结果保存到向量库中。
- 在实际识别时，眼镜拍摄到的人脸图像会上传到后端，后端同样使用模型将当前人脸转换为特征向量，并与向量库中的历史向量进行相似度匹配。
- 当匹配结果达到设定阈值后，系统即可得到对应学生的学号。学号并不是最终展示结果，而是后续查询学生业务信息的关键索引。
- 在获得学号后，后端再调用学校统一身份认证体系或学生信息服务接口，获取该学生的基本信息，并将整合后的结果返回给客户端。
- 自动识别模式适合迎新、巡查等需要持续观察的场景；手动识别模式则适合教师在特定节点下主动触发一次识别，减少无关抓拍与系统负载。

### 2.5 结果展示说明

识别成功后，系统会展示学生的核心信息，包括但不限于姓名、学号、学院、专业、班级和年级等内容。上述信息既可在手机端查看，也可同步显示在眼镜端自定义视图中。教师可在校园巡查、学生咨询、课堂观察和考试检查等场景下，快速完成学生身份识别与信息调取，从而提升信息获取效率与辅助决策能力。

实现原理说明：

- 结果展示由手机端和眼镜端协同完成。手机端负责接收后端返回的数据并进行页面渲染，眼镜端则通过 `CXR-M SDK` 的自定义视图能力同步展示关键识别结果。
- 为保证佩戴体验和阅读效率，眼镜端通常只显示最核心的信息，避免一次性展示过多内容影响视野；手机端则可承担更完整的信息展示与交互。
- 在实际应用中，系统可根据不同场景对展示内容进行裁剪。例如迎新场景下可优先突出姓名、身份核验状态与必要提示信息，以兼顾效率、隐私保护与服务体验。
- 通过“识别结果返回手机端”与“核心信息同步显示到眼镜端”的双端协同方式，教师或工作人员可以在保持自然交流的同时获取辅助信息，提升现场服务质量。
